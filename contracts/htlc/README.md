# HTLC

## Specification
The Hash Timed Locked Contract (HTLC) involves two users, the *owner* and the *verifier*, and it allows the owner to commit to a secret and reveal it afterwards, within a given deadline. 

The commitment is the SHA256 digest of the secret (a bitstring). At contract creation, the owner specifies the verifier, who will receive the collateral in case the deposit is not revealed within the deadline. 

The deadline expires 1000 blocks after the block where the contract has been deployed: if deployment is at block N, `timeout` can be called in a block with height strictly greater than N+1000.

After contract creation, the HTLC allows the following actions:
- `commit` requires the owner to deposits a collateral (at least 1 ETH) in the contract, and records the commitment;
- `reveal` allows the owner to withdraw the whole contract balance, by revealing a preimage of the committed secret;
- `timeout` can be called by anyone only after the deadline, and tranfers the whole contract balance to the verifier.

## Properties
- **balance-only-increases-on-commit**: If the contract balance is increased after a transaction, then the transaction must be a `commit`
- **cant-uncommit**: If contract is in a committed state, no transaction should be able to reverse it back to an uncommited state
- **commit-auth-owner**: If a `commit` transaction does not revert, then `msg.sender` must be the contract's owner
- **commit-minimum**: If a `commit` transaction does not revert, then the contract balance should increase by at least `fee` ETH
- **commit-reverts-if-isCommitted**: If contract is already in a committed state, then any following `commit` transaction must revert
- **commit-twice-reverts**: After a `commit` transaction that does not revert, any immediately following `commit` transaction must revert
- **contract-balance-is-commit-value**: After a `commit` transaction that does not revert, the contract's balance must be equal to the transaction's value
- **owner-immutable**: No succesful transaction can change contract's owner
- **reveal-auth-owner**: If a `reveal` transaction does not revert, then the transaction's sender must be the contract's owner
- **reveal-timeout-after-isCommitted**: A `reveal` or `timeout` transaction won't revert only if contract is in a committed state
- **reveal-transfer**: If a `reveal` transaction does not revert, `owner`'s balance must increase by at least the balance of the contract
- **reveal-zeroes-balance**: If a `reveal` transaction does not revert, it must completely drain the contract's balance
- **sent-le-init-bal**: The overall amount transferred from the contract does not exceed the initial deposit.
- **timeout-deadline**: If a `timeout` transaction does not revert, the transaction must have occurred at a block number greater than or equal to the contract's initial block plus `waitTime`
- **timeout-transfer**: If a `timeout` transaction does not revert, `verifier`'s balance must increase by at least the balance of the contract
- **timeout-zeroes-balance**: If a `timeout` transaction does not revert, it must completely drain the contract's balance
- **verifier-immutable**: No succesful transaction can change the address of the verifier
- **wrong-preimage-reverts**: If a `reveal(s)` transaction does not revert, then `s` is a preimage of the committed hash

## Versions
- **v1**: conformant to specification.
- **v2**: removed check that `commit` can only be called before `reveal` and `timeout`.
- **v3**: `timeout` can be called since block N+999 (included).
- **v4**: `timeout` transfers balance to `msg.sender` instead of verifier.
- **v5**: removed check that `commit` can only be called by `owner`.
- **v6**: removed check that `reveal` can only be called by `owner`.
- **v7**: `reveal` and `timeout` reset `isCommitted` to `false`
- **v8**: removed check that revealed string is a pre image of committed hash
- **v9**: removed check that `commit` should be called with a `msg.value` of at least 1 ETH.
- **v10**: call to `reveal` transfers balance to `verifier` instead of `owner`
- **v11**: `timeout` transfers balance to owner instead of verifier.
- **v12**: `reveal` function may be bribed to change committed `hash`
- **v13**: `timeout` function may be bribed to change `verifier` address
- **v14**: `reveal` function may be bribed to change `owner` address
- **v15**: `commit()` can be successful even if `isCommitted` was true before the call.
- **v16**: all methods always revert.
- **v17**: all methods do nothing.
- **v18**: all methods do nothing, but revert when they're supposed to.
- **v19**: the contract has a new `hashing2` method that's the same as `hashing`.
